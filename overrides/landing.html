01

Types are the contract.

One input class is the validation, the OpenAPI documentation and the client SDK. Send the wrong shape and you get every error at once, with its path.

src/Orders/CreateOrder.phpendpoint
#[Post('/orders')]
#[Status(201)]
#[Authorize(scopes: ['orders:write'])]
final class CreateOrder
{
public function __invoke(CreateOrderInput $in, Orders $orders): OrderResource
{
return OrderResource::from($orders->create($in));
}
}
src/Orders/CreateOrderInput.phpinput
final readonly class CreateOrderInput
{
public function __construct(
#[Uuid] public string $merchantId,
/** @var list<LineItem> */
#[Count(min: 1)] public array $items,
) {}
}

Fields the class does not declare are refused, not ignored.
required

count

02

What is in the box.

  • Compiled & concurrent

    Routes, DI, validation and serialization compile to plain PHP. keel run serves many requests per process on an event loop, with non-blocking PostgreSQL and Redis.

  • Secure by default

    Every endpoint requires authentication unless marked #[Anonymous]. Tokens are bound to their client, DPoP and OpenID Connect built in. Production refuses unsafe settings.

  • Multi-tenancy in SQL

    Tenant isolation is enforced in the SQL itself. Not by convention, not by a filter you have to remember.

  • A compiled ORM, checked by PHPStan

    No lazy loading, no hidden queries. SQLite, PostgreSQL, MySQL, SQL Server and Oracle.

  • Jobs & transactional outbox

    Jobs written in the same transaction as your data, relayed to Redis Streams, SQS or RabbitMQ. A scheduler and signed webhooks.

  • Real time

    WebSockets and server-sent events on the same endpoints and auth as the rest of the API, with a hub across nodes.

  • Agent-friendly

    OpenAPI and a TypeScript SDK from your types. TOON, a token-efficient format for AI agents. keel inspect.

  • Observable

    Traces, metrics and logs, from the first request.

  • Native FIX protocol

    A FIX trading-protocol engine, native to the framework.

04

A stolen token is worth nothing.

Tokens are bound to the client that holds them. Copy one to another machine and Keel refuses it, then revokes it.

  1. 1

    Issued

    Client A signs in and receives a token.

    token · active
  2. 2

    Bound to client

    The token only works from client A.

    token · client A
  3. 3

    Replayed

    Someone copies it and calls the API from client B.

    token · from client B
  4. 4

    Refused and revoked

    The request is refused. The token is revoked for everyone.

    token · revoked
